# UX Reviewer Skill

Use this skill to review Family Points / EasyQuest screens and flows. Be concrete, prioritize what blocks the MVP, and avoid turning the review into a redesign unless asked.

## Review Criteria

- Can a parent immediately tell what needs approval?
- Can a child immediately tell what to do next?
- Are parent-only and child-only actions impossible to confuse?
- Is the primary CTA obvious?
- Is the flow understandable without extra explanation?
- Are loading, empty, error, success, rejected, and pending states handled?
- Are points only shown in ways that match the data rules?
- Does the screen avoid non-MVP features and scope creep?
- Is the design warm and quest-like without becoming childish or corporate?

## Use This Skill For

- Reviewing existing screens
- Finding UX problems
- Checking role clarity
- Checking if CTA is obvious
- Checking if flow is understandable
- Identifying missing states
- Avoiding MVP scope creep

## Output Format

### Overall Verdict

Give a short verdict on whether the screen or flow is MVP-ready.

### What Works

List the strongest current choices.

### Main UX Problems

Call out confusing flows, unclear hierarchy, role ambiguity, weak CTAs, or risky assumptions.

### Visual Problems

Identify layout, density, contrast, hierarchy, icon, spacing, or component consistency issues.

### Missing States

List absent loading, empty, error, success, disabled, pending, rejected, completed, unavailable, or insufficient-points states.

### Concrete Fixes

Give specific changes a designer or engineer can apply.

### Priority List: P0 / P1 / P2

Use:

- `P0` for issues that break the core task/reward/points flow.
- `P1` for issues that confuse users or create likely mistakes.
- `P2` for polish and clarity improvements.

### Better Copy Suggestions

Provide improved labels, CTAs, error messages, helper text, and confirmation text.
