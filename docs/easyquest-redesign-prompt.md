# EasyQuest Professional Mobile Redesign Prompt

Нужно разработать несколько профессиональных вариантов дизайна мобильного приложения EasyQuest. Это не landing page, не moodboard и не набор абстрактных карточек. Нужны реальные mobile-first экраны приложения, готовые к переносу в React Native/Expo.

EasyQuest — детско-семейное приложение для заданий, баллов, наград, целей, накоплений, достижений и мотивации. Интерфейс должен быть ярким, дружелюбным, игровым и эмоциональным, но выглядеть как зрелый продовый мобильный продукт, а не сырой детский шаблон.

## Важный Контекст Текущего Приложения

Перед дизайном внимательно изучить текущие файлы:

- `src/app/child/dashboard.tsx` — текущий главный экран ребенка, карточка баллов с пиратом, компактный уровень, серия, цель.
- `src/shared/ui/RocketProgressBar.tsx`
- `src/shared/ui/RocketProgressBar.web.tsx`
- `src/shared/ui/RocketProgressBar.module.css` — это эталонный progress bar, его нельзя заменять обычной полоской.
- `src/shared/ui/QuestIcons.tsx` — текущие иконки приложения.
- `src/shared/ui/BottomActionBar.tsx` — текущая нижняя навигация.
- `src/shared/ui/AppCard.tsx`, `PointsBadge.tsx`, `StatusBadge.tsx`, `SegmentedControl.tsx`, `FocusLiftCard.tsx`.
- `src/app/child/tasks.tsx`, `rewards.tsx`, `balance.tsx`, `achievements.tsx`, `growth-missions.tsx`.

## Эталонный Progress Bar

Progress bar должен быть взят из текущего приложения, а не нарисован заново.

Его визуальные признаки:

- Высота track: 24px.
- Track темный теплый: `rgba(102, 58, 0, 0.38)`.
- Border: `1px solid rgba(255,255,255,0.16)`.
- Fill — золотая сегментная заливка:
  - deep coin edge `#D06F08`
  - brand gold `#F7B721`
  - shine `#FFD84D`
  - warm edge `#FFC838`
- На fill есть diagonal stripes и soft highlight.
- Есть золотой glow на конце fill.
- Вариант со свинкой: runner `pig-running-coins-progress.png`, размер примерно 60x40, стоит на конце прогресса.
- Вариант без свинки: `showRunner=false`, `showGlow=false`, используется для reward/wish/cards, где runner не нужен.

Нельзя:

- заменять progress bar простой синей/зеленой полоской;
- делать плоский generic progress;
- менять runner на другого персонажа;
- использовать свинку отдельно от progress bar там, где нужен именно bar.

## Карточка Баллов

Карточка баллов должна быть почти как текущая удачная версия в `child/dashboard.tsx`, но визуально отполирована.

Обязательные признаки:

- Компактная hero-карточка, не огромный баннер.
- Внутри: label `Мои баллы`, монета, крупное число баллов, маленький pending pill.
- Пират расположен справа и частично выходит по вертикали, но не ломает карточку.
- Контент и пират находятся выше glow layer, без проблем z-index.
- Карточка должна выглядеть как главная игровая финансовая карточка ребенка.
- Не добавлять внутрь лишние кнопки, лишние микрокарточки или много текста.

Цвет можно адаптировать под концепцию, но геометрия и роль должны сохраняться.

## Карточка Уровня

Карточка уровня должна быть компактной.

Обязательно:

- Без свинки.
- Без пирата.
- С аватаром/иконкой достижения, уровнем, rank label, XP text.
- Использовать progress bar без runner или компактный вариант, если это уровень/achievement.
- Не делать карточку уровня второй большой hero-карточкой.

## Серия

Серия — это маленький status block.

Обязательно:

- Небольшой блок рядом или под уровнем.
- Не крупная карточка.
- Не использовать персонажей.
- Ясная метрика: `7 дней серии`, flame/bolt/flag-like visual можно делать UI-native, но без emoji.

## Главная Цель / Копилка

Главная цель должна показывать накопление к награде.

Обязательно:

- Использовать эталонный progress bar со свинкой-runner.
- Можно использовать иконку копилки `piggy-bank-mascot.png` или `icon-kopilki.svg` как маленький icon label.
- Не использовать большую отдельную свинку-иллюстрацию поверх карточки, если она конкурирует с progress bar.
- Карточка должна быть структурной: title, price/balance, progress, remaining.

## Задания

Карточки заданий должны опираться на текущий паттерн `src/app/child/tasks.tsx`.

Обязательные признаки:

- Карточка с полно-высотным цветным icon block слева.
- Иконка внутри блока должна быть аккуратная и крупная.
- Справа: title, description, footer.
- Footer: PointsBadge с монетой + action button.
- Не использовать случайные маленькие emoji.
- Не делать все карточки одинаковыми бледными белыми прямоугольниками.
- Состояния: available, pending, done, rejected.

## Награды / Желания

Использовать текущий паттерн:

- `FocusLiftCard` для выбранной главной цели.
- `PointsBadge` с монетой.
- `StatusBadge`.
- Progress bar без runner/glow для обычных reward/wish progress.
- Основной CTA: redeem / choose / not enough points.
- Карточки должны выглядеть как магазин наград, но без желтого перегруза.

## Нижняя Навигация

Навигация должна сохранять текущий состав и реальные иконки:

- Дом
- Квесты
- Баллы
- Награды
- Миссии

Текущий паттерн:

- Белая/ice панель.
- Верхние скругления около 34px.
- Иконки крупные, около 38px.
- Label 11px, жирный.
- Active state цветом, но без тяжелой плашки под каждым пунктом.
- Badge count для квестов/наград.

Не делать маленькую web-style nav bar с микроскопическими иконками.

## Нужно Сделать Несколько Цветовых Концепций

Сделать 4-5 вариантов. Каждый вариант должен выглядеть как реальный продукт, а не просто перекрашенная копия.

### Вариант 1: Classic EasyQuest

- Основной синий `#1647B7`.
- Navy/graphite `#10233F` / `#16283A`.
- Лайм `#D8FF3E` как active accent.
- Золото `#F7B721` для баллов и наград.
- Светлый голубой фон `#EDF5FF`.
- Максимально близко к текущему стилю.

### Вариант 2: Tropical Adventure

- Cyan/turquoise как основной accent.
- Синий оставить для важных CTA и статуса.
- Лайм умеренно.
- Ощущение карты, острова, приключения, сокровищ.
- Без декоративного хаоса и без новых иллюстраций.

### Вариант 3: Treasure Gold

- Теплый золотой и оранжевый accent.
- Синий как балансирующий цвет.
- Подходит для rewards, coins, chest.
- Не делать весь интерфейс желтым.

### Вариант 4: Night Quest

- Темный navy/graphite только для ключевых hero-зон.
- Светлые карточки для читаемости.
- Лайм и золото как яркие акценты.
- Premium, но все еще child-friendly.

### Вариант 5: Candy Quest

- Мягкие pink/cyan/lime/blue акценты.
- Для младших детей.
- Не уходить в приторный, сырой или nursery-style UI.
- Структура карточек должна остаться взрослой и читаемой.

## Какие Экраны Показать

Для каждого цветового варианта показать минимум:

1. Главный экран ребенка.
2. Задания.
3. Награды.
4. Баллы / копилка / история.
5. Достижения / уровень.
6. Миссии роста / накопления.

На главном экране обязательно показать:

- компактную карточку баллов с пиратом;
- компактную карточку уровня без свинки;
- маленький блок серии;
- главную цель с эталонным progress bar со свинкой;
- 1-2 карточки задания;
- нижнюю навигацию с текущими иконками.

## Критерии Качества

Дизайн должен выглядеть так, будто его делал senior mobile product designer.

Проверить перед сдачей:

- Все иконки текущие, не emoji.
- Progress bar соответствует текущему компоненту.
- Есть оба варианта progress bar: со свинкой и без.
- Карточка баллов компактная и похожа по роли/геометрии на текущую удачную версию.
- Карточка уровня без свинки.
- Пират не используется в каждой карточке.
- Свинка не используется как случайный большой персонаж.
- Карточки заданий имеют сильный визуальный паттерн с left color block.
- Нижняя навигация похожа на мобильную app navigation, а не web tabs.
- Тексты не переполняют карточки.
- Нет landing page.
- Нет moodboard.
- Нет абстрактных фреймов без реальных данных.
- Нет сырых маленьких карточек с плохими отступами.

## Формат Результата

Сделать дизайн-доску с 4-5 концепциями. В каждой концепции показать реальные экраны приложения, а рядом кратко указать:

- palette tokens;
- роли цветов;
- правила использования пирата;
- правила использования свинки;
- варианты progress bar;
- states для cards/buttons/badges/navigation.

Главная цель результата — выбрать визуальное направление, которое можно сразу переносить в текущую React Native codebase без переписывания бизнес-логики.
